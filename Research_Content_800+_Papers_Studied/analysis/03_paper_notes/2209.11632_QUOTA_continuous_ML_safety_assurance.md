## Content (own words)
- Problem: ML in safety-critical use (automotive, now avionics) must be treated as a CONTINUOUS
  engineering process (per ISO 21448 / SOTIF, appendix D). Core challenge: when the deployment
  environment CHANGES (new shop floor, regulation, robot config), a safety argument valid in one
  context may NO LONGER hold. Need to accelerate re-assurance.
- Method: extend standard ML-Ops with an explicit link to an ASSURANCE CASE. Baseline snapshot =
  (1) deployed ML system incl. pre/post-processors, (2) a SAFETY CASE in Goal-Structuring
  Notation (GSN) arguing the engineering is rigorous and ML output insufficiency is not a source
  of credible harm, (3) for each piece of evidence, the document/tool result demonstrating it.
  Associate SEMANTIC TAGS with safety-case argumentation; turn each evidence into a quantitative
  metric or logic formula. On a change (from incident reports, context evolution, or onboard
  monitoring like near-collision / OOD detection), run a QUERY over the safety-argument tree to
  highlight which evidence has turned INVALID → targeted re-work instead of full re-assurance.
  Exemplified on a vision-based emergency-braking AGV in factory automation.
