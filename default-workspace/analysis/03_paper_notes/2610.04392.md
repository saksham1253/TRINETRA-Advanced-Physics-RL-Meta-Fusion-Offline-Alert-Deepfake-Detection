## Problem & why it matters
Existing anomaly-detection (AD) benchmarks are SATURATED and unrealistic. This challenge builds a
HIDDEN-TEST, application-driven benchmark across two deployment-critical domains (industrial defect
segmentation = MVTec AD 2; retail logistics = Kaputt 2) and makes computational EFFICIENCY a
first-class metric. It is a model for how to design an honest, deployment-oriented evaluation — the
exact doctrine TRINETRA needs for its hazard-detection claims (FM-21 metric mirage, Rule 16).

## Core idea / method (benchmark design, re-usable)
- Tracks: Industrial (MVTec AD 2, pixel-level segmentation) + Retail (Kaputt 2, detection AP), each
  with a REGULAR setting (train on normal data) and a ZERO-SHOT setting (no task-specific training).
- HIDDEN test set (private leaderboard) — prevents test-set tuning / leakage.
- Metrics: Segmentation F1 (industrial, pixel-level, private split SegF1_priv), Average Precision
  (retail), plus a NEW computational-EFFICIENCY metric combining performance, throughput, memory,
  and power under a unified hardware setting assessed after the deadline.
- Submission requires reproducible open-source code + weights + a technical report (anti-leakage,
  pro-reproducibility governance).

## Data / splits / generalization
- MVTec AD 2 (industrial), Kaputt 2 (retail) + a new low-prevalence retail set (Kaputt-Rare) to
  probe rare-defect performance. Private hidden test. Efficiency measured on unified hardware.

## Key results (as stated in prose; tables pruned)
- Industrial: best regular-setting method ~57% pixel-level SegF1 → unsupervised AD segmentation is
  FAR from solved. Zero-shot trails by ~15 SegF1 points → task-specific training on normal data
  remains essential for precise localization.
- Robustness to distribution shift is a key open challenge; DINOv3 backbones dominate that axis.
- Retail: supervised common-defect detection near saturation; best off-the-shelf VLM trails
  specialized models by ~28 AP (VLMs CANNOT yet replace fine-tuned detectors); reference images did
  not help top methods; performance COLLAPSES on rare defects (spillage ~53 AP, missing units ~27 AP).
- Efficiency largely neglected: top methods use heavy architectures; the community needs
  efficiency-aware methods + true rare-defect / shift robustness.

## Assumptions & limitations
- Domain is manufacturing/retail, NOT video surveillance or hazards — transfer is by DOCTRINE, not
  by direct dataset. Preprint/challenge-report; leaderboard tables not re-read.
