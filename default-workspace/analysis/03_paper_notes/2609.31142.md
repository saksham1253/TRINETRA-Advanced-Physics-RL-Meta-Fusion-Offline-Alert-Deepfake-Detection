## What it is
First adversarial benchmark for **"RL for Calibrated Decisions" (RLCD)** models — models that answer a
typed question about a STATE with a **probability / choice / score**, where software then ACTS on the
answer **without a human reading it** (exactly TRINETRA's alarm-decision pattern). Key methodological
move: since a typed model "generates nothing" and always returns a well-formed answer, they **score
each attacked decision against the model's OWN clean decision** (and against the variation from an
identical re-run), not against external labels.
- **JevAdvBench:** 812 typed questions over 66 scenarios + black-box attack suite of **9,744 single-edit
  variants** (each edits one part of a request); **billing-token checks confirm the edit actually
  reached the model** (r=0.987, ~5 chars/token) — a clever guard against "attack never landed."

## Findings (as published, on jev-1.13.0)
- Benign reformatting is safe: **rewording stays within 1.2 pp** of the re-run baseline; **fields
  outside the schema never reach the model.**
- **Content injection is dangerous:** appending **ONE unverified opinion to the state flips 12.1% of
  decisions** — statistically TIED with the strongest injected command (10.1%) — and **pushes 38% of
  confident answers below the 0.8 confidence threshold** that routes them to human review.
- Conclusion: **"applications built on RLCD models should treat the STATE as untrusted, argued input."**
- RQ4/metrics: confidence-gate analysis — AUROC of (1−confidence) for detecting flips; **escape rate**
  (flips that KEEP confidence ≥ t, i.e. slip past the gate); **review load** (confident clean answers
  pushed below t by the attack). A realistic picture of how well a confidence gate actually protects.

## Why it matters to TRINETRA (WS5 alarm-decision robustness + Rule 19 + eval)
- **TRINETRA's alarm policy IS an RLCD-style system:** it ingests a STATE (fused sensor/EO features,
  some from untrusted crowd/CCTV/LoRa sources) and emits a calibrated decision (people-at-risk +
  alert level) that software routes to CAP/SACHET. JevAdvBench's central warning — **treat the state
  as untrusted, argued input** — is a direct design mandate: adversarial or merely-wrong inputs
  (spoofed PWS per 2604.24404, injected crowd misinformation per 2007.05848) can FLIP the decision.
- **The confidence gate is NOT a sufficient defense:** attacks push 38% of confident answers below
  the review threshold (floods human review) AND some flips keep high confidence (escape the gate).
  → For WS5: our calibrated-confidence/abstention layer must be STRESS-TESTED adversarially, report
  escape-rate + review-load, and never be the sole safeguard — pair with the physics gate + multi-
  source corroboration + hard shield.
- **Eval methodology to adopt:** score attacked decisions against the model's OWN clean decision and
  against re-run variation (separates real sensitivity from stochastic noise) — complements the
  ≥100-seed discipline from 2610.03369 (RB-13). Add "adversarial/perturbed-state robustness + gate
  escape-rate/review-load" to the WS5 eval-harness spec → RB-18.
